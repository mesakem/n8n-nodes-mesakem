# חבילת n8n של מסכם: הסבר קצר לבעלים

## מה זה
חבילה ל-n8n בשם `n8n-nodes-mesakem`. משתמש מתקין אותה ב-n8n, מדביק מפתח API של מסכם, ובונה אוטומציות בלי קוד.

יש בה שני רכיבים:
- **Mesakem Trigger**: מפעיל workflow ברגע שקורה משהו במסכם. למשל: סיכום מוכן, פגישה הסתיימה, תמלול מוכן, משימות חדשות. יש 24 סוגי אירועים.
  - מסכם שולח את האירוע בעצמו (webhook). אין בדיקה חוזרת כל כמה דקות (polling), ולכן אין עומס על מסד הנתונים.
- **Mesakem**: פעולות.
  - פגישות: פגישה אחת, רשימה, סיכום, תמלול, פגישות קרובות.
  - משימות: קריאה, יצירה, עדכון, ביטול.
  - בוט: לשלוח, לתזמן, לבטל.
  - מסמך, ופרטי המפתח (me).

## מה חשוב לדעת
- **אין עלות חדשה.** החבילה קוראת רק ל-API הקיים. אין בה AI ואין "ask".
- **אבטחה.** כל אירוע נבדק לפי החתימה (Standard Webhooks). אירוע מזויף נדחה, ולא נשלחת בגללו אף בקשה ל-API.
- **מעט בקשות.** כל אירוע עולה לכל היותר 2 בקשות API, כדי להביא את הפרטים לפי מזהה.
- **Free / ניסיון:**
  - קריאה עובדת.
  - כתיבה (משימות, בוט) מחזירה הודעה ברורה שצריך תוכנית בתשלום.
  - טריגר אוטומטי צריך תוכנית בתשלום. במצב "Manual" גם משתמש Free יכול: הוא מוסיף את הכתובת בעצמו בהגדרות כ-webhook היחיד שלו, ומדביק את הסוד.
- **הטקסטים באנגלית בלבד**, כי n8n דורשים את זה לאימות.

## מה אתה צריך לעשות כדי לפרסם (ידני)
1. **ריפו ציבורי.** לפתוח ריפו ציבורי חדש ב-GitHub, למשל `mesakem/n8n-nodes-mesakem`, ולהעתיק אליו את התיקייה הזו. אם הכתובת שונה, לעדכן את `repository` ב-`package.json` ואת הקישורים ב-`nodes/*/*.node.json`.
2. **חשבון npm.** לפתוח חשבון ב-npmjs.com (או ארגון `mesakem`) ולהפעיל אימות דו-שלבי.
3. **פרסום ראשון.**
   - ליצור ב-npm טוקן עם הרשאת publish.
   - לשמור אותו בריפו כ-secret בשם `NPM_TOKEN`.
   - במחשב, בתוך התיקייה, להריץ `npm install` ואז `npm run release`. הפקודה מעלה גרסה ודוחפת tag, וה-GitHub Action מפרסם ל-npm עם provenance.
   - `npm publish` רגיל חסום בכוונה, כי n8n דורשים פרסום דרך GitHub Actions.
4. **אחרי הפרסום הראשון.** ב-npm, להגדיר Trusted Publisher לריפו ולקובץ `publish.yml`, ולמחוק את הטוקן.
5. **בדיקה.** להריץ `npx @n8n/scan-community-package n8n-nodes-mesakem`.
6. **אימות.** להגיש את החבילה ב-n8n Creator Portal. אחרי שהיא מאומתת, היא מופיעה גם ב-n8n Cloud.

## איך לבדוק מול staging
1. ליצור מפתח ב-staging (הגדרות ← API ו-Webhooks). לטריגר צריך הרשאת "ניהול Webhooks" ותוכנית בתשלום או `internal_test`.
2. ב-n8n, ב-credential, לשנות את ה-Base URL ל-`https://staging.mesakem.com/api/v1`.
3. לטריגר צריך n8n עם כתובת https ציבורית. `localhost` לא יעבוד.
4. להפעיל workflow, לסיים פגישה קצרה, ולבדוק שמגיע item עם `signature_verified: true`.
